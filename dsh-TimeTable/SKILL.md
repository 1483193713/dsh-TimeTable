# TimeTable：把当前任务排进 DeepSeek 谷时

把用户此刻的请求延迟到**下一个 DeepSeek 谷时起点**执行：用 `schedule_create` 在当前会话建一条定时提醒，到点后由会话继续把任务做完。

## 峰谷规则（北京时间 Asia/Shanghai）

| 时段 | 判定 |
|---|---|
| 周一至周五 09:00–12:00 | 高峰 |
| 周一至周五 14:00–18:00 | 高峰 |
| 工作日 00:00–09:00、12:00–14:00、18:00–24:00 | 谷时 |
| 周六、周日全天 | 谷时 |
| 法定节假日全天（按国务院放假通知的放假日期） | 谷时 |

边界：09:00:00 起算高峰，12:00:00 起算谷时，14:00:00 起算高峰，18:00:00 起算谷时。

**调休上班的周六/周日仍按谷时处理**（规则写的是「周末全天」谷时，不因调休上班变成高峰）。若要改成「调休上班日按工作日算」，得在脚本里加一份 `workdays` 覆盖清单并同步改 `classify()`，不要只改 `holidays.json` —— 那里只登记放假日期。

## 排期规则

1. **此刻在高峰** → 目标 = 当前这段高峰的结束时刻：上午段排到同日 12:00，下午段排到同日 18:00。
2. **此刻已在谷时**（工作日早晚/午间、周末、节假日）→ 谷时已在生效，不再空等：**立即执行当前任务，不建定时任务**，并明确告诉用户「当前已是谷时，已直接执行」。
   - 只有用户明确要求「即使现在是谷时，也要排到下个谷时起点」时，才按「等过下一段高峰」计算（脚本 `--wait-next`）。

## 执行步骤

1. **固化「当前任务」**：写成自包含的 prompt —— 目标、范围与文件路径、约束、验收标准、要产出的东西。
   定时任务到点时，会话只能看到这条 prompt，拿不到发送时的对话结论，所以必须写全。
   如果任务还缺关键信息、需要用户拍板，先用 `ask_user_question` 问清楚再排期，别把半成品任务排进队列。
2. **算目标时间**（不要心算，直接跑脚本）。

   技能目录 = 本 `SKILL.md` 所在目录（本机默认 `%USERPROFILE%\.dsh\skills\timetable`，macOS/Linux 为 `~/.dsh/skills/timetable`）。Python 用 `load_workspace_dependencies` 返回的那个；没有就用 `python` / `python3`。脚本只用标准库。

   ```powershell
   # Windows
   & <python> "<技能目录>\scripts\next_offpeak.py"          # 人类可读
   & <python> "<技能目录>\scripts\next_offpeak.py" --json   # 机器可读
   ```
   ```bash
   # macOS / Linux
   python3 "<技能目录>/scripts/next_offpeak.py" --json
   ```

   - `action=schedule` → 按返回的 `target` 建定时任务；`action=run_now` → 直接执行。
   - 脚本会打印判定依据：今天是否节假日、当前落在哪个区间、目标为什么是它。
   - 输出含 `WARN 20xx 年法定节假日数据缺失` → 先 `web_search` 国务院办公厅当年放假通知，补进 `references/holidays.json` 再排期；补不了就在回复里注明「按周末规则近似」。
3. **建定时任务**：`schedule_create`
   - `title`：只写任务主题（动词 + 对象，≤ 40 字），**不要**写日期、时间、「定时」「谷时」这类调度信息。
   - `at`：`{"date": "<target_date>", "time": "<target_time>", "time_zone": "Asia/Shanghai"}`，显式写北京时间，别依赖浏览器时区。
   - `prompt`：原任务的自包含描述 + 到点说明，例如：
     > 【TimeTable 定时任务】现在已进入 DeepSeek 谷时（北京时间 2026-11-02 12:00，此前为高峰）。请直接执行以下任务，并把结果汇报给用户：<任务正文>
4. **回报**：一句话说清「当前是否高峰 / 排到几点 / 距现在多久 / 已建定时任务」，并提示可用 `schedule_list` 查看、`schedule_delete` 取消。

## 判定示例（脚本 `--selftest` 覆盖）

| 现在（北京时间） | 结论 |
|---|---|
| 周一 10:30 | 排到 12:00 执行 |
| 周一 15:10 | 排到 18:00 执行 |
| 周一 11:59 | 排到 12:00 执行 |
| 周一 07:30 / 13:00 / 20:00 | 已是谷时 → 立即执行 |
| 周六 10:00、周日 15:00 | 已是谷时 → 立即执行 |
| 2026-02-17（春节，周二）10:30 | 已是谷时 → 立即执行 |
| 2026-01-04（周日，调休上班）10:30 | 按「周末全天谷时」→ 立即执行 |

## 注意

- `schedule_create` 是**会话级**提醒：到点把 prompt 投回当前会话继续跑；换会话或关掉会话后不会在别处执行。
- 一个任务只留一条活跃提醒。重复触发先 `schedule_list`：目标时刻相同时复用或 `schedule_update`，别再建第二条。
- 12:00 / 18:00 是整点切换，脚本就排整点；不要自己改成 11:59 或 12:05。
- 任务很便宜、或用户显然是想现在就要结果时，先用一句话确认再延迟，别默认排期。
- 节假日数据只登记「放假」日期，不登记调休上班日；`references/holidays.json` 里某个年份的 `ranges` 为 `[]` 表示该年通知尚未发布，脚本会告警。
- 脚本检测不到 `Asia/Shanghai` 时区数据（Windows 上缺 `tzdata` 包）会自动退回固定 `+08:00`——中国无夏令时，结果不受影响。
